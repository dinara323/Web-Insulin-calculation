Ветка `lab5-react` создана от `cookies` (коммит `c3b850e985d83955288314b3b8a148a4cd81ee1d`).

## Запуск

Для фронтенда нужен Node.js 22+ и npm. Из корня репозитория:

```sh
cd frontend
npm ci
npm run dev
```

Открыть http://localhost:5173. При первом открытии сразу показаны три mock-карточки.
Это позволяет показать пункты 7.1–7.3 без сервера и без подключения к интернету.
Для загрузки данных своего сервера нажмите «Искать» (пустой поиск загружает весь список).

Для работы с реальными данными предварительно запустите существующий NestJS
из корня репозитория по `README_LR4.md`, с его PostgreSQL, Redis и MinIO.
Настройки и данные сервера эта лабораторная не меняет.
Фронтенд обращается к NestJS по адресу http://localhost:3000.
Если сервер работает, например, на порту 3004, создайте `frontend/.env.local`:

```dotenv
API_TARGET=http://localhost:3004
```

После изменения переменной перезапустите Vite.
Если порт 5173 занят, используйте `npm run dev -- --port 5174` и откройте порт 5174.
Запросы проксируются через Vite, поэтому менять CORS сервера не требуется.

## Сборка

В папке `frontend/`:

```sh
npm run build
npm run preview
```

Первая команда проверяет TypeScript и создаёт `frontend/dist/`.
Вторая запускает локальный просмотр сборки на http://localhost:5173
с тем же прокси к API. `dist/` и `node_modules/` в коммит не включаются.
Публикация на внешнем хостинге в эту работу не входит.

## Docker (раздел 9 методички)

В папке `frontend/`:

```sh
docker compose up --build
```

Открыть http://localhost:5173. Работают hot reload и монтирование исходников.
NestJS запускается отдельно на компьютере; контейнер обращается к нему через
`http://host.docker.internal:3000`. При другом порте измените `API_TARGET`
в `frontend/docker-compose.yml`. При занятом внешнем порте можно заменить
проброс на `5174:5173`.

Остановка: `docker compose down` из `frontend/`.
Существующие compose-файлы в корне не изменены.

## Соответствие методичке

| Требование | Реализация |
|---|---|
| React, TS, Vite, функциональные компоненты | `frontend/package.json`, `src/main.tsx`, компоненты и страницы |
| Props, состояние, жизненный цикл | Props в `InputField`, `ServiceCard`, `TabBar`; `useState`, `useEffect`; отмена запросов при уходе со страницы |
| React Router, два экрана | `/` — список, `/detail/:id` — подробности; `Routes.ts`, `main.tsx` |
| Разделение на компоненты и сетевой модуль | `components/`, `pages/`, `modules/servicesApi.ts` |
| Колонка 390 px, один столбец карточек | `MobileApp.css`; на меньших экранах ширина 100% |
| Общий массив через Outlet context | `AppLayout.tsx`; без Redux и отдельного React Context |
| Поиск и mock | `ServicesPage.tsx`, `modules/mock.ts`: поиск по началу названия без учёта регистра; если совпадений нет — весь mock, как в п. 7.1 |
| Дефолтное изображение | `public/DefaultImage.jpg`, `ServiceImage.tsx`; также при ошибке загрузки картинки |
| Нижняя таб-панель | `TabBar.tsx`: «Расчёты» ведёт на `/`, «Подробнее» — на первую карточку текущего списка, активная вкладка подсвечена |
| Медиа на экране «Подробнее» | `DetailPage.tsx`: видео `autoPlay`, `loop`, `muted`, `playsInline`; при отсутствии/ошибке видео — изображение |
| Кнопка «Далее» | Следующая запись текущего массива; ID не увеличивается арифметически; последняя карточка отключает кнопку |
| Собственный API | `GET /api/services?name=...`, `GET /api/services/feed?id=...`; поля соответствуют существующему NestJS |
| CORS | Vite proxy без удаления `/api`; `credentials: 'include'` сохраняет поддержку cookies ЛР4 |
| Docker | `frontend/Dockerfile`, `.dockerignore`, `docker-compose.yml`; host, polling, strictPort |

В методичке iTunes — учебный пример. Здесь он заменён предметной областью
репозитория: расчётами чувствительности к инсулину.
Поля `imageUrl`, `videoUrl`, `age`, `weight`, `sensitivityCoefficient`
берутся из существующего API. При прямом открытии URL неизвестная общему
массиву карточка загружается через `/api/services/feed?id=...`.
При ошибке запроса выполняется поиск в mock по ID; неизвестный ID показывает
«Расчёт не найден». Источник данных указан над списком.
При возврате со страницы подробностей сохраняются поисковая строка и результаты.

## Проверка на защите

1. Откройте приложение без NestJS: три карточки и заглушки вместо отсутствующих фото.
2. Нажмите первую карточку: `/detail/1`; «Далее» ведёт на `/detail/4`, затем `/detail/9`.
3. На последней карточке «Далее» отключена. Нижняя вкладка «Подробнее» снова открывает первую карточку.
4. Вернитесь в «Расчёты», найдите `Пример`: одна mock-карточка, её открывает вкладка «Подробнее».
5. Введите несуществующее имя: отображается весь mock, как в п. 7.1.
6. Запустите NestJS с опубликованными расчётами. Очистите поиск и нажмите «Искать»: источник сменится на «Данные собственного API».
7. Проверьте поиск, открытие карточки, «Далее» и обновление прямого URL `/detail/<id>`.
8. Для карточки с доступным `videoUrl` показывается видео; без видео — фото/заглушка.
9. Проверьте узкое окно и широкое окно: колонка не шире 390 px, панель закреплена снизу.
